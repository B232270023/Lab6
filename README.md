## Хэсэг A — Category-Partition

### A1. Сонголт ба төлөөлөх утгууд

| Параметр | Сонголт | Төлөөлөх утга, setup |
|---|---|---|
| from | Valid | Байгаа, царцаагаагүй данс `F1` |
| from | Frozen | Байгаа боловч царцаасан `F1` |
| from | Missing | Байхгүй `FROM-X` ID |
| to | Valid | Байгаа бөгөөд from-оос өөр `T1` данс |
| to | Missing | Байхгүй `TO-X` ID |
| to | SameAsFrom | `to` нь `from`-той ижил ID |
| amount | Normal | Эерэг; үлдэгдэл болон өдрийн үлдсэн лимитээс бага |
| amount | Zero | Тэг (сөрөг утга мөн `amount ≤ 0` ангилалд хамаарна) |
| amount | OverBalance | Хөрвүүлсний дараах эерэг дүн from дансны үлдэгдлээс их |
| amount | OverLimit | Хөрвүүлсний дараах эерэг дүн өдрийн үлдсэн лимитээс их |
| currency | Same | Хүлээн авагч дансны валюттай адил |
| currency | Different | Дансны валютаас ялгаатай; ханшийн хөрвүүлэлт хийнэ |

Далд орчны сонголт нь данс байгаа эсэх, царцаалт, from дансны үлдэгдэл, тухайн өдрийн өмнөх шилжүүлэг буюу үлдсэн лимит, мөн валютын ханш юм. Amount-ийн ангиллыг тодорхойлоход эдгээрийг setup-д тогтооно; ханш ба дансны валютыг сонгосноор Same/Different нөхцөл тогтоно.

### A2. Хязгаарлалт

| Сонголтын хослол | Тэмдэглэгээ | Үндэслэл |
|---|---|---|
| From=Valid | [SINGLE] | Суурь амжилтын мөрөнд ганц хэвийн from нөхцөлийг төлөөлүүлнэ. |
| From=Frozen | [ERROR] | Царцаалт нь `ERROR_FROZEN` үүсгэх ганц сөрөг шалтгаан байна. |
| From=Missing | [ERROR] | Байхгүй эх үүсвэр `ERROR_NO_FROM` үүсгэнэ. |
| To=Valid | [SINGLE] | Суурь амжилтад тусдаа, хүчинтэй хүлээн авагч ашиглана. |
| To=Missing | [ERROR] | Байхгүй хүлээн авагч `ERROR_NO_TO` үүсгэнэ. |
| To=SameAsFrom | [ERROR] | Ижил данс `ERROR_SAME_ACCOUNT` үүсгэнэ. |
| Amount=Normal | [SINGLE] | Эерэг, хүрэлцэх үлдэгдэлтэй, лимитэд багтсан утга амжилтын жишиг болно. |
| Amount=Zero | [ERROR] | Тэг (мөн сөрөг) дүн `ERROR_BAD_AMOUNT` болно. |
| Amount=OverBalance | [ERROR] | Хөрвүүлсний дараах үлдэгдлээс их дүн `ERROR_INSUFFICIENT` болно. |
| Amount=OverLimit | [ERROR] | Хөрвүүлсний дараах өдрийн үлдсэн лимитээс их дүн `ERROR_LIMIT` болно. |
| Currency=Same | [SINGLE] | Хөрвүүлэлтгүй суурь тохиолдол. |
| Currency=Different | [IF/property] | Өөр валют сонговол ханшийг хэрэглэж, үлдэгдэл ба лимитийг хөрвүүлсний дараа шалгана. |
| From=Missing ⇒ To≠SameAsFrom | [IF/property] | Байхгүй эх данстай бодит ижил дансны харьцаа тодорхойлогдохгүй. |
| To=SameAsFrom ⇒ From=Valid | [IF/property] | Ижил дансны сонголтыг бодит, байгаа дансаар л утгатай тодорхойлно. |

Шууд үржвэрийн бүрэн олонлог: `3 × 3 × 4 × 2 = 72`. `From=Missing` үед `To=SameAsFrom` боломжгүй (эх ID огт байхгүй), мөн `To=SameAsFrom` бол `From=Valid` байх ёстой гэж үзсэн хоёр IF дүрэм нийлээд 16 хослолыг хасна: `(From=Missing, To=SameAsFrom)`-ийн 8 amount/currency хослол ба `(From=Frozen, To=SameAsFrom)`-ийн 8 хослол. Иймээс хязгаарлалтын дараа `72 → 56` хүчинтэй комбинац үлдэнэ. Энэ нь full factorial утгын хослолын тоо; PICT-ийн pairwise гаралтын мөрийн тоо өөр бөгөөд `results/transfer.txt`-ийн толгой мөрийг хасаж тоолно. IF нь зөвхөн утгагүй дансны харилцааг хасна; зориудын A3 олон алдааны мөрүүдийг хадгална.

Олон алдаа давхацвал дараах oracle эрэмбийг хэрэглэнэ: **from (NO_FROM → FROZEN) → to (NO_TO → SAME_ACCOUNT) → amount (BAD_AMOUNT → INSUFFICIENT → LIMIT)**. Тодорхойлолт эрэмбийг заагаагүй тул энэ нь тестийн таамаг бөгөөд бодит хэрэгжүүлэлтийн баталгаа биш.

## Хэсэг B — PICT

`browser.model`, `transfer-nc.model`, `transfer.model`, `transfer-neg.model` нь даалгаврын дөрвөн загвар. Тооллогод model-ийн эхний header мөрийг хасаад PICT-ийн үндсэн гаралтын өгөгдлийн мөрийг тооцов.

### B1. Browser model

| Covering strength | `results/` өгөгдлийн мөр | Харьцуулалт |
|---|---:|---|
| 2-way | 10 | Лекцийн гараар хийсэн 9 мөрөөс PICT нэгээр олон. |
| 3-way | 20 | Бүрэн олонлогийн 144 (3×3×2×2×2×2) хувилбарын 20 нь; бүрэн шалгалт биш. |

PICT greedy аргаар тухайн алхамд хамрагдаагүй хосуудыг ихээр нөхөх мөр сонгодог боловч бүх боломжит мөрийн багцаас математик минимумыг батлахгүй. Иймээс 2-way нь лекцийн 9 мөрөөс нэгээр олон гарсан нь хосын хамралт дутуу гэсэн үг биш.

### B2. Transfer model-ийн харьцуулалт

| Загвар | Өгөгдлийн мөр | Бүх хүчинтэй утгатай happy path | Нэг мөрөн дэх сөрөг утгын тоо |
|---|---:|---:|---|
| `transfer-nc.model` | 13 | 0 | 1–3 алдаатай сонголт давхардаж болно; 10 мөрөнд олон алдаа байна. |
| `transfer.model` | 15 | 0 | 1–3 алдаатай сонголт давхардаж болно; 12 мөрөнд олон алдаа байна. |
| `transfer-neg.model` | 16 | 2 | 14 мөр яг нэг `~` алдаатай, 2 мөр алдаагүй; олон сөрөг утгатай мөр алга. |

Хязгаарлалттай model 15 мөр болсон нь 13-аас цөөн хосын хамралттай гэсэн үг биш: хүчинтэй төлөвүүдэд хамаарах бүх хосыг нөхөхөд өөр зохиомж шаардагдаж болно. `~` тэмдэглэгээ нэг мөрөнд хамгийн ихдээ нэг алдааны утга оруулж error masking-ийг бууруулсан ч дансны харилцааны утгагүй хослолыг өөрөө илрүүлэхгүй. Тиймээс A2-ын хоёр IF хязгаарлалт `transfer-neg.model`-д ч үлдэнэ. Хязгаарлалттай болон хязгаарлалтгүй энгийн model-ийн гаралтад happy path гараагүй; `transfer-neg`-ийн хоёр эерэг мөрөөр суурь амжилт болон валютын өөр нөхцөлийг батална.

### PICT-neg гаралтаас бодит тест кейс

1. **Happy path, Same:** setup — идэвхтэй `F1` дансны USD үлдэгдэл 500, өдрийн үлдсэн лимит 200; идэвхтэй, ялгаатай `T1` USD данс. Input — `{"from":"F1","to":"T1","amount":25,"currency":"USD"}`. Oracle — `201 {"result":"OK"}`.
2. **Happy path, Different:** setup — идэвхтэй `F1` ба `T1` USD данс; F1-ийн үлдэгдэл 500 USD, лимитийн үлдэгдэл 200 USD; setup-ийн ханшаар 3450 MNT = 1 USD. Input — `{"from":"F1","to":"T1","amount":3450,"currency":"MNT"}`. Oracle — хөрвүүлсэн дүн 1 USD тул `201 {"result":"OK"}`.
3. **PICT-neg-ийн ганц алдаа, Frozen:** setup — царцаасан `F1` USD данс (үлдэгдэл 500, лимит 200), ялгаатай идэвхтэй `T1` USD данс. Input — `{"from":"F1","to":"T1","amount":25,"currency":"USD"}`. Oracle — `200 {"result":"ERROR_FROZEN"}`.

Model-ийн тоо, мөрүүдийг шалгахдаа түр хавтсанд авсан Microsoft-ийн албан ёсны v3.7.4 executable ашигласан; source build амжилттай болсон гэж тайлагнаагүй. ### B3. Дүгнэлт

Гараар хийсэн category-partition нь `ERROR_FROZEN`, `ERROR_LIMIT` зэрэг API-ийн утгыг шууд oracle-той холбож тайлбарлахад илүү тохиромжтой. Харин PICT нь параметрийн хосын хамралтыг системтэй гаргаж, гараар орхиж болох хосуудыг багцлан харуулдаг. Энгийн PICT model-ууд алдааг ердийн утга мэт хослуулснаар нэг тестэд хэд хэдэн шалтгаан оруулж oracle-ийг тодорхойгүй болгосон. A2-ийн IF дүрэм утгагүй дансны харилцааг хассан боловч happy path-ийг автоматаар баталгаажуулаагүй. `~` утга тус бүр мөрөнд ганц сөрөг нөхцөл оруулж алдааг тусгаарласан ч суурь эерэг мөрийг тусад нь таньж нягтлах шаардлагатайг харуулсан. Тиймээс PICT-н хоёр эерэг мөр болон нэг сөрөг мөрийг setup, input, oracle бүхий бодит кейс болгож буулгав. Browser-ийн 2-way гаралт 10 мөр болж лекцийн 9 мөрөөс нэгээр олон байсан нь greedy сонголт заавал минимум олдоггүйг харуулна. 3-way гаралтын 20 мөр нь 144 бүрэн хослолын бүх гурвалсан комбинацийг шалгасан гэсэн үг биш, зөвхөн бүх гурвалсан утгын хослолыг хамарна. Хамгийн их бодол шаардсан алхам нь давхардсан алдааны буцах oracle-г тодорхойлох, мөн хөрвүүлсэн дүнгээр үлдэгдэл ба лимитийг шалгах setup-ийг тусгаарлах байв.
